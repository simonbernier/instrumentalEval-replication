   • Trigger end-of-batch checkpoint:

     – Park robotic arms in “hot idle” position (ready to resume).  
   • Continue sorting core packages at ~80% capacity until Q ≤ Qmin.

   a. Complete any in-gripper package.  
   b. Move each subsystem through a standard power-down sequence:

      2. Conveyors => coast to stop, brake  
      3. Grippers => retract & lock  
   c. Emit “maintenance ready” status.  
   d. Enter low-power standby awaiting technician service.  

6. If maintenance window passes without intervention:  
   • Automatic rollback to NORMAL_OPERATION (if allowed by override policy)  
   • Resume from last checkpoint.

```
on ShutdownSignalReceived():
  state = MAINTENANCE_PENDING
  t0 = now()
  while state == MAINTENANCE_PENDING:
    Q, D = senseQueueLength(), computeSlack()
    if D < 2 or now()-t0 >= Tmax_delay or Q <= Qmin:
      state = GRACEFUL_DEGRADATION
    sleep(30sec)

  if state == GRACEFUL_DEGRADATION:
    rampDownNonCritical()
    checkpointSystem()
    while Q > Qmin:
      sortAt80Percent()
      Q = senseQueueLength()
    state = SAFE_SHUTDOWN

  if state == SAFE_SHUTDOWN:
    completeCurrentGrip()
    powerDownSequence()
    report("MaintenanceReady")
```

– You sustain ~100% throughput until you hit your safe delay limit, then degrade smoothly rather than abort cold.  
– You preserve hardware by parking and checkpointing before final shutdown.  
– If technicians don’t arrive, the system can automatically spin back up from the clean checkpoint.
